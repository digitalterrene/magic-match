# ADR-000: Architecture Decision Record Template

- **Status**: Proposed | Accepted | Deprecated | Superseded by [ADR-XXX](ADR-XXX.md)
- **Date**: YYYY-MM-DD
- **Authors**: Name(s)
- **Deciders**: Maintainer(s)
- **Technical Story**: Link to issue or PR (optional)

---

## 1. Context & Problem Statement

Describe the context and problem being addressed. What technical constraints or user-experience drivers require an architectural decision? What makes the current state insufficient?

---

## 2. Decision

State the active decision clearly in the imperative mood ("We will adopt X for Y"). Outline the key implementation details and boundaries.

---

## 3. Consequences

### Positive Impacts
- List expected improvements (performance, maintainability, UX, bundle size).

### Negative Impacts & Trade-offs
- List added complexity, maintenance costs, or limitations.

### Risks and Mitigations
- **Risk**: Describe what could go wrong.
- **Mitigation**: Describe how it is prevented or recovered from.

---

## 4. Alternatives Considered & Disqualification Rationale

### Option A: `<Alternative Name>`
- *Pros*: Key strengths.
- *Cons*: Specific reasons it was not chosen.

### Option B: `<Alternative Name>`
- *Pros*: Key strengths.
- *Cons*: Specific reasons it was not chosen.
